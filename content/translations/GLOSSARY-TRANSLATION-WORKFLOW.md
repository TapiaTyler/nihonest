# Japanese glossary translation workflow

The English glossary records are canonical. The Japanese catalog is `src/data/translations/ja/glossary-translations.ts`; the focused revision checks are in its adjacent test. Read those files and `docs/LOCALIZATION-ROLLOUT-PLAN.md` before starting another batch. Do not infer coverage from a prior chat or a historical count in a document. The shared prompt is `content/translations/JAPANESE-STRUCTURED-CONTENT-PROMPT.md`, and protected terminology is in `src/data/translations/ja/protected-terminology.ts`. Claude receives only the selected records and relevant instructions; it does not need the whole repository or permission to edit it.

## One bounded batch

1. Assign an Explorer subagent to identify five untranslated canonical term IDs and extract only their `shortDefinition`, `detailedExplanation`, and `commonContext` fields. Compare the IDs with the current Japanese catalog before spending a Claude call. The subagent should flag legal, administrative, or terminology distinctions that require close review.
2. Give Claude exactly those five English records, their stable IDs and Japanese headwords, the rules in `JAPANESE-STRUCTURED-CONTENT-PROMPT.md`, and relevant protected terms. Ask for JSON containing only the ID and three translated fields. Tell Claude not to browse, edit files, add facts, or expand the batch. Use a fresh one-shot session and a budget limit; do not ask Claude to inspect the whole repository. Retain its raw output until review is complete.
3. Give a separate Reviewer subagent the raw output and the five English records for legal, immigration, tax, healthcare, or other high-stakes terminology. Require a per-term pass or precise correction for meaning, qualifications, official terms, and natural Japanese. A Codex review does not change `reviewState` to `human-reviewed`.
4. Apply accepted or corrected fields once. Use `claude-code-codex-reviewed` and the actual Claude model in the new artifacts' generator metadata. Preserve existing entries and their provenance. Generate `sourceRevision` from the three canonical English fields; keep the shared terminology and prompt revisions current. Do not retranslate unchanged records.
5. Update the focused test's count, verify unique IDs and revisions, and give a Tester subagent only the focused lint and translation tests. Run broader checks only when a failure or cross-cutting edit justifies them. Update the current coverage snapshot and report any check that could not run. Keep the result `machine-translated` until a qualified human reviews the exact artifact revision.

## Delegation and handoff

The primary agent owns the selection, provenance, high-stakes wording decisions, and final response. Explorer selects and extracts; Claude drafts only the three Japanese fields; Reviewer checks substantive fidelity independently; a bounded Implementer may integrate approved fields when that saves time without competing edits; Tester checks the changed translation catalog. Do not spawn agents merely to satisfy a count, and do not have two agents edit the same file concurrently. State which roles actually ran and whether the Claude call succeeded.

After each batch, report the new term IDs and coverage, the exact checks and any blockers, two or three local glossary links for manual review, and the next bounded batch. Do not commit or push unless asked. Until the user confirms a push, keep one **consolidated** suggested commit message covering all relevant unpushed work, not a new message for each batch. Supply only the `git commit -m "..."` and `git push` command lines in the handoff; if files are not staged, say that the user must stage the intended files first. Once the user confirms a push, start a fresh consolidation window. Never describe a code or editorial review as qualified human approval.

## Trial result and next decision

The September 23, 2026 pilot used Claude Sonnet 5 on `tennyu-todoke`, `shiyakusho`, `kuyakusho`, `kokumin-kenko-hoken`, and `kokumin-nenkin`. Independent Codex review accepted two as written and corrected three wording problems before integration. The errors narrowed 市役所 and 区役所 to service counters and described insurance premiums as something a municipality “operates.” A second five-term batch covered `honnin-kakunin`, `futsu-yokin`, `daigaku`, `tanki-daigaku`, and `daigakuin`. Review accepted three as written and corrected two: a circular identity-verification definition and a graduate-school explanation that narrowed non-degree research and changed eligibility into fit. The second call used an isolated, tool-free one-shot prompt and cost about $0.04, compared with about $0.20 for the first repository-aware call. A later three-term Claude Opus 5.5 comparison passed two entries as drafted; independent review caught a material departure-from-Japan omission in the third. These results support small reviewed Claude batches; they do not support unattended publication or qualified editorial approval. If future batches repeatedly need substantive correction, pause the Claude batch workflow and revise the prompt or model choice before generating more.
